# LingLearn Cloud 视频推荐算法方案

## 1. 目标

本方案用于支撑首页 `for_you` 视频流推荐，满足以下业务目标：

- 新用户默认使用冷启动推荐
- 老用户根据观看、点赞、收藏、评论、分享等行为形成兴趣画像
- 对用户感兴趣的分类、标签、作者进行定向推送
- 在“命中兴趣”和“避免信息茧房”之间保持平衡
- 方案优先可落地，先规则化，再逐步演进到模型化

当前仓库还没有正式后端代码，因此本文件以“后端实现规范”的形式定义算法、数据流和表设计。

## 2. 推荐场景

首页视频流建议区分三种场景：

### 2.1 新用户冷启动

适用于：

- 注册后无任何观看行为
- 近 7 天有效行为过少
- 用户兴趣画像尚未形成

推荐策略：

- 50% 平台热门内容
- 30% 高质量新内容
- 20% 探索性内容（覆盖不同分类）

### 2.2 成长用户兴趣推荐

适用于：

- 已有有效观看行为
- 已形成分类 / 标签 / 作者偏好

推荐策略：

- 以兴趣召回为主
- 叠加热视频、关注作者、相似标签
- 混入一定比例探索内容

### 2.3 回访用户唤醒

适用于：

- 一段时间未活跃
- 最近回流

推荐策略：

- 最近高热内容
- 用户曾强互动的分类内容
- 最近 7 天新增优质内容

## 3. 核心思想

推荐分为四步：

1. 行为采集：记录观看、点赞、收藏、评论、分享等动作
2. 兴趣建模：把行为转成分类、标签、作者三个维度的兴趣分
3. 候选召回：从多个来源召回一批候选视频
4. 排序打分：结合用户兴趣分、内容热度、时效性、去重和探索策略输出最终列表

第一期不依赖复杂机器学习模型，直接采用“多路召回 + 规则排序 + 分数衰减”的方式，便于快速上线和调参。

## 4. 用户行为定义

### 4.1 正向行为

对推荐最有价值的行为建议按强弱排序：

1. 评论
2. 收藏
3. 分享
4. 点赞
5. 完播
6. 高观看时长 / 高观看进度
7. 二次回看

### 4.2 负向行为

当前产品没有单独的“不感兴趣”按钮，因此第一期负反馈可从行为反推：

- 曝光后快速划走
- 多次曝光仍不点击 / 不观看
- 观看进度明显偏低
- 同类内容持续低停留

### 4.3 有效观看判定

建议将一次观看是否计入兴趣画像做阈值过滤：

- `watch_seconds >= 5`
- 或 `watch_progress >= 15`
- 或发生了点赞 / 收藏 / 评论 / 分享任一强互动

未达到有效观看条件时，只作为弱信号或负信号处理。

## 5. 兴趣画像建模

## 5.1 分类兴趣分

每个用户对每个 `category_id` 维护一个兴趣分 `category_interest_score`。

单次行为对分类分值的贡献建议如下：

| 行为 | 建议分值 |
| --- | --- |
| 浏览但停留 < 5 秒 | -1 |
| 有效观看 | +2 |
| 观看进度 >= 50% | +3 |
| 完播 | +5 |
| 点赞 | +6 |
| 收藏 | +10 |
| 评论 | +12 |
| 分享 | +8 |
| 二次回看 | +4 |

额外建议：

- 长视频可按 `watch_progress` 优先，而不是只看 `watch_seconds`
- 对连续多次低停留的分类，分值应缓慢下降

## 5.2 标签兴趣分

如果视频绑定了 `content_item_tags`，则同一行为分值按标签均分或按主标签权重分摊。

例如：

- 用户收藏了一条有 2 个标签的视频
- 收藏分值为 `+10`
- 每个标签可加 `+5`

标签兴趣分比分类更细，适合做精准召回。

## 5.3 作者兴趣分

如果用户多次观看、点赞、收藏某位作者内容，应形成作者偏好。

建议维护 `author_interest_score`，典型用途：

- 首页对喜欢的作者加权
- 作者发布新内容时优先推荐

## 5.4 时间衰减

兴趣不是永久不变的，建议所有兴趣分带时间衰减。

简单做法：

- 最近 3 天：权重 `1.0`
- 4 到 7 天：权重 `0.8`
- 8 到 15 天：权重 `0.5`
- 15 天以上：权重 `0.2`

也可以使用指数衰减：

```text
decay_weight = exp(-days / 7)
```

最终行为贡献：

```text
final_behavior_score = raw_behavior_score * decay_weight
```

## 6. 内容侧质量分

除了用户兴趣，还需要一个内容公共质量分，避免只推“用户看过类似”的低质内容。

建议复用或扩展 `content_items.hot_score`，计算逻辑示例：

```text
hot_score =
  views_count * 0.05 +
  likes_count * 1.00 +
  favorites_count * 1.50 +
  comments_count * 1.80 +
  shares_count * 1.20 +
  recency_bonus
```

其中：

- `recency_bonus`：新内容加分，随发布时间递减
- 审核未通过、未发布、被删除内容不可进入推荐池

## 7. 候选召回策略

首页 `for_you` 建议至少使用 5 路召回：

### 7.1 热门召回

来源：

- `content_items.hot_score`

作用：

- 保障内容质量下限
- 适合新用户

### 7.2 分类兴趣召回

来源：

- 用户兴趣分最高的前 N 个分类

作用：

- 命中用户宏观兴趣

### 7.3 标签兴趣召回

来源：

- 用户兴趣分最高的前 N 个标签

作用：

- 命中用户细粒度兴趣

### 7.4 作者偏好召回

来源：

- 用户近 15 天强互动较多的作者

作用：

- 提升熟悉作者内容的点击率和停留时长

### 7.5 探索召回

来源：

- 用户较少触达但平台质量较高的内容
- 新分类、新标签、新作者

作用：

- 防止信息茧房
- 给新内容机会

## 8. 排序打分策略

候选召回后，建议对每条视频计算最终排序分：

```text
rank_score =
  category_match_score * 0.30 +
  tag_match_score * 0.25 +
  author_match_score * 0.10 +
  behavior_similarity_score * 0.10 +
  hot_score_norm * 0.15 +
  recency_score * 0.05 +
  explore_score * 0.05
```

可先这样定义各项：

- `category_match_score`：用户对该分类的兴趣分，归一化到 0 到 100
- `tag_match_score`：该内容标签在用户标签兴趣中的匹配得分
- `author_match_score`：用户对作者的偏好分
- `behavior_similarity_score`：若内容同时命中多个高兴趣标签 / 分类，则加分
- `hot_score_norm`：内容热度归一化分
- `recency_score`：新内容加分
- `explore_score`：探索内容保底分

## 9. 去重与打散

首页推荐不能只按分数直排，建议做三类约束：

### 9.1 已看内容降权

对最近 3 天已完整看过的视频：

- 默认不重复推荐
- 或大幅降权

### 9.2 同作者打散

连续 3 条内不建议出现同一作者的多个视频。

### 9.3 同分类打散

连续 4 条内同分类不超过 2 条，避免刷屏感。

## 10. 新用户冷启动算法

新用户默认使用“平台默认推送算法”，建议规则如下：

```text
冷启动列表 = 50% 热门 + 30% 新内容 + 20% 探索内容
```

其中探索内容要求：

- 分类尽量均匀覆盖
- 优先选高质量内容
- 避免全是同一主题

当用户产生以下任一行为后，开始逐步切换到个性化推荐：

- 有效观看 >= 10 次
- 点赞 / 收藏 / 评论累计 >= 3 次
- 某一分类累计兴趣分超过阈值

建议切换逻辑：

- 前 20 条推荐中，冷启动与个性化混排
- 随行为增长逐步提高个性化比例

示例：

- 第 1 天：80% 默认 + 20% 个性化
- 第 3 天：50% 默认 + 50% 个性化
- 行为稳定后：20% 默认 + 80% 个性化

## 11. 行为更新策略

推荐不建议每次请求临时全表计算，建议拆成两层：

### 11.1 实时层

用户发生行为后，实时更新：

- `content_view_histories`
- 点赞 / 收藏 / 评论等交互表
- 用户兴趣画像聚合表

适合：

- 观看进度上报
- 点赞 / 收藏 / 评论回调

### 11.2 离线层

定时任务每 5 分钟或 1 小时做一次：

- 计算内容 `hot_score`
- 重算用户兴趣衰减
- 清理过旧曝光数据
- 生成部分推荐缓存

## 12. 推荐接口建议

现有文档里已经有：

- `GET /feed/videos`

建议扩展内部实现逻辑，但接口仍保持不变。

查询参数建议保留：

- `cursor`
- `limit`
- `category_id`
- `recommend_type`

其中 `recommend_type` 建议支持：

- `for_you`
- `following`
- `hot`
- `cold_start`

后端内部逻辑：

- 若用户无兴趣画像，则 `for_you` 自动走 `cold_start`
- 若用户兴趣画像已形成，则走个性化推荐

## 13. 推荐所需新增数据表

当前表结构已有：

- `content_items`
- `content_item_tags`
- `content_likes`
- `content_favorites`
- `content_comments`
- `content_view_histories`

这些表可以支撑第一期，但若要把推荐做稳，建议增加三类表：

### 13.1 用户分类兴趣画像表

用途：

- 存储用户对分类的聚合兴趣分
- 避免每次推荐临时扫行为表

### 13.2 用户标签兴趣画像表

用途：

- 支撑细粒度兴趣推荐

### 13.3 推荐曝光日志表

用途：

- 记录“推荐过但没点开”的负反馈
- 统计 CTR、完播率、收藏率
- 后续支持 A/B 实验

## 14. 推荐流程伪代码

```python
def recommend_for_user(user_id: int, limit: int, cursor: str | None):
    profile = load_user_interest_profile(user_id)

    if profile.is_cold_start:
        candidates = recall_cold_start_candidates(limit=500)
    else:
        candidates = merge_candidates(
            recall_by_hot(limit=200),
            recall_by_categories(user_id, top_n=5, limit=200),
            recall_by_tags(user_id, top_n=10, limit=200),
            recall_by_authors(user_id, top_n=20, limit=100),
            recall_by_explore(user_id, limit=100),
        )

    ranked = []
    for content in candidates:
        if should_filter_content(user_id, content):
            continue

        score = calc_rank_score(user_id, content)
        ranked.append((content, score))

    ranked.sort(key=lambda item: item[1], reverse=True)
    ranked = diversify(ranked)
    ranked = paginate_by_cursor(ranked, cursor, limit)
    log_impressions(user_id, ranked)
    return ranked
```

## 15. 第一阶段实现建议

建议按下面顺序落地：

1. 先保证 `watch-progress`、点赞、收藏、评论接口能稳定写入行为表
2. 增加兴趣画像聚合表与推荐曝光表
3. 实现“冷启动 + 分类兴趣召回 + 热门召回”
4. 再补标签兴趣召回、作者偏好召回、探索打散
5. 最后再考虑协同过滤或学习排序模型

## 16. 第一阶段调参建议

初始权重建议：

- 停留 / 有效观看：低到中权重
- 点赞：中权重
- 收藏 / 评论：高权重
- 分享：高权重
- 完播：中高权重

如果首页目标更偏“停留时长”，可提高观看和完播权重。

如果首页目标更偏“用户价值”，可提高收藏、评论、分享权重。

## 17. 后续演进方向

第一期上线后，可逐步演进：

- 引入协同过滤：喜欢相似内容的用户互相启发
- 引入序列推荐：根据最近 10 条行为建模短期兴趣
- 引入学习排序模型：预测点击率、完播率、收藏率
- 引入 A/B 实验：对比不同权重和召回策略效果

## 18. 最终结论

这个项目当前最适合的后端推荐方案，不是一步到位上复杂 AI 模型，而是：

- 新用户走默认热视频 + 新内容冷启动
- 老用户基于观看时长、完播、点赞、收藏、评论、分享形成分类 / 标签 / 作者兴趣画像
- 多路召回后按规则排序
- 用曝光日志和时间衰减持续修正用户偏好

这样既符合当前数据库结构，也最适合后续在 `FastAPI` 服务中快速落地。
